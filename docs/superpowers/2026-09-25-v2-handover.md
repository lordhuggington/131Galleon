## 3. Deferred findings (not fixed, all Minor)

**Backend** — IntegrityError attribution in `create_user`/`update_user`; `backup.sh` hard-codes `data/photos`;
a photo can be attached to any date, not just a visit date; upload writes the file before the row (orphan on
a failed INSERT); `/api/state` ships the full photo list with no bound; caption travels in the query string and
`/photos/*` are served with a 7-day immutable cache (spec §8.2); `app/cli.py` imports `app.api` (layering);
CLI `set-password` also sets `active = 1` (the break-glass reactivates a deactivated staff member);
CLI `set-phone --clear` signs the person out but API `PATCH {"phone": ""}` does not (person left with no
phone, no hash, live sessions); `create-user` prints "Ignored --password" before the INSERT (a duplicate-phone
failure prints it then errors); `store.get_settings` would 500 `/api/state` if a seeded `settings.json` had a
non-dict `tue`/`fri`.

**API contract change to know about** — `POST /api/users` with role staff + phone + password is now 400
("They sign in by text, so they don't need a password.").

**Frontend** — the whole-branch reviewer's remaining trade-off: adding `wantPlan` to the refresh signature
means every tab switch produces a `server-state` dispatch even when the data is unchanged (re-runs
`TaskRowEditor`'s sync effects, re-seeds `MealSettingsCard`'s form; widens the "concurrent refresh can revert
an optimistic tick for ≤ 20 s" window to include tab changes). Plus the per-task deferrals:

- `client.ts` spreads `...init` (a caller could override headers); `api<T>()` does no runtime validation of
  response bodies; `setUnauthorizedHandler` is a single module-global; `console.warn` logs `ApiError` bodies in
  `refresh()`/`loadPlan()`; an identical consecutive toast is not re-announced; a stalled logout request keeps
  polling until it resolves; a non-401 failure of the plan/users fetch inside `refresh()` aborts the whole resync.
- `aria-expanded` without `aria-controls`; `AccountPanel` mounted (closed) for owners too; reveal-button
  `aria-label` wording; the masked door code in `PersonRow` has no accessible name ("••••").
- Photos: unreachable "Choose a photo first." guard; file input auto-resets on a partial-batch retry (display
  only); fixed element ids (v1 parity); the UNSUPPORTED notice is dropped if a later upload fails.
- Meals: Stop pressed before the POST resolves sends no cancel; a double-click on Create can double-POST (the
  server's 409 absorbs it); "cancelling" tick text overwrites "Stopping…"; a second failed Copy doesn't reselect
  the textarea; favourite-star double-tap PATCHes twice.
- Setup: stale `useActionState` error on reopen; `Number("")` → 0 in a numeric field (native `min` blocks
  submit); the reducer clears `ui.confirm` on user-active/delete-task.
- Shell: `history.replaceState`-only hash mirror, so the browser Back button exits the app (brief-mandated);
  one-frame wrong hash + one extra `/api/state` on a staff `#setup` boot; boot treats offline/5xx as signed-out.
- Docs: README has two consecutive "Open http://…" lines; "1 GB is plenty" is now optimistic; ARCHITECTURE
  omits `@types/*` from its dev-dep list.
- Tests: no unit test covers `refresh()`'s signature short-circuit or `<Activity>` reveal semantics (by plan:
  no component tests); formatter tests are ICU-sensitive; `macros.test.ts` uses a cast.

   work against the v2 API; the container builds the v2 frontend itself.
3. **HEIC uploads were never exercised** — the resize path was verified with PNG → JPEG 1600×1200 only. Try one
   iPhone HEIC after deploy.
4. **Local scratch data** — `data/house.db` (gitignored) contains the smoke-test users `owen`, `maria` and
   `tester`. Their passwords are the ones written into the smoke-test task of the frontend plan (a public file),
   so delete `data/` or run `python3 -m app.cli set-password --username <name>` before pointing anything real at
   that database.

   they have one.
